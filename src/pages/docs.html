A — Getting started

Installing

Download {{installerFile}} from the download page and run it. Setup asks whether to install for all users (Windows asks for permission) or only for you (no administrator rights), shows a short "Before you install" page, and can open Sentinel when it finishes. It needs {{windows}}; nothing else, no Python and no command line.

The installer is not code-signed yet, so Windows SmartScreen may warn about it. The download page explains what the warning means and how to check the file.

First-run setup

The first time Sentinel opens, a four-step setup appears over the main window.

  1. Welcome. What Sentinel does and what it does not do. Not Now closes setup; reopen it from Help → Run Setup Again.
  2. Protected locations. Your personal folders, ticked; OneDrive, if present, unticked. Untick anything you don't want watched.
  3. Initial scan. Choose whether protection should start every time Sentinel opens, then press Start Protection. Skip Scan ends the scan early; monitoring keeps running.
  4. Protection active. Continue to the guided tour, the dashboard or the Safe Demo.

The guided tour outlines one real control at a time; replay it from Help → Guided Tour. Help → Quick Reference (F1) is a one-page summary.

Protected locations

The Protected Locations page lists every folder and whether it can actually be watched. A folder stays listed whatever its state.

StateMeaning
WatchedActivity in the folder is observed while protection runs.
CoveredInside another protected folder, which is watched instead.
MissingNot there right now (a disconnected drive, for example). Watched again when it returns.
No accessSentinel runs with your permissions and cannot read it.
JunctionA link that could point elsewhere. Not followed.
OffYou unticked it.

Add Location… adds any folder; a whole drive, the Windows folder or Program Files gets a warning first. Re-check asks every folder for a fresh answer.

Starting protection

Use the toolbar (Ctrl+Shift+M to start, Ctrl+Shift+S to stop) or the protection panel on the dashboard.

StateMeaning
PROTECTION OFFNothing is watched.
STARTING PROTECTIONLocations are being checked (up to about 15 seconds for slow network folders).
INITIAL SCANMonitoring is running; existing files are being listed by name.
PROTECTION ACTIVEContinuous monitoring of every watchable location.
STOPPINGProtection is being stopped.
PROTECTION NOT STARTEDSomething failed; the message names it.

Protection runs only while Sentinel is open, and Sentinel does not start with Windows on its own. Open it when you start your computer; with Start protection automatically when Sentinel opens ticked, it starts watching straight away.

Safe Demo

The Demo Center shows the whole workflow without ransomware. It creates, edits and renames inert text files in its own workspace inside Sentinel's data folder. It encrypts nothing, touches none of your files, ends no process and changes no setting; everything after the synthetic files is the real product.

  1. Open Demo Center and press Start Demo. If protection is off, the demo starts monitoring and stops it again on reset.
  2. Follow the progress list. Each step turns green only when the product has done it.
  3. Open the incident and press Acknowledge; then Verify Audit Chain and Assess Recovery.
  4. Press Reset Demo…. The synthetic files are removed and the demo incident is dismissed; its records are kept.

Start Demo is refused while another incident is active, so a demo alert can never merge into a real case.

B — Using Sentinel

Alerts and incidents

A risk score of 60 (HIGH) or more raises an alert, and alerts from one episode are grouped into one incident. How it works explains the signals, the score and the bands. Open an incident from the dashboard's Next step or the Incidents page. It shows the forensic record's status, the response options, what was observed (risk, attribution, files affected, first and last seen), why it is suspicious, what happened to each file, and a timeline of every action.

StatusMeaning
OPENNew; nobody has acted on it.
INVESTIGATINGYou marked it as being looked into.
CONTAINED / QUARANTINEDA file attributed to it was contained.
RESOLVEDClosed after investigation.
DISMISSEDClosed as not a threat, for example a demo incident or your own activity.

When an alert appears

  1. Don't delete anything yet. Open the incident and read Why this is suspicious and File activity.
  2. Were you changing many files at once? Then it may be you.
  3. If it wasn't you: disconnect from the network, run a full scan with Microsoft Defender or your antivirus, and check your backups. Sentinel does not stop programs itself.
  4. Record the outcome: Mark Investigating, then Mark Resolved… or Dismiss….

Security posture

The posture is Sentinel's verdict on its own monitoring, not on the computer: PROTECTED, MONITORING, DEGRADED, ERROR, CRITICAL THREAT or MONITORING OFF. PROTECTED means monitoring is working on your protected locations. DEGRADED names what is not fully working, such as events shed under heavy load, notifications Windows dropped, records that could not be saved, or a folder still being checked. Only a CRITICAL incident changes the posture to CRITICAL THREAT; while a HIGH incident is open the posture stays PROTECTED and says so.

Quarantine and restore

Quarantine is offered only when an incident names a program file. Attribution is usually UNKNOWN, so often there is nothing to quarantine, and Sentinel says so.

Quarantining moves the file into Sentinel's store under a generated name without an executable extension, and records its SHA-256. This is containment, not isolation: a program running as you can still read the stored bytes, and Sentinel does not stop the program. Restoring checks the file byte-for-byte against its recorded hash, refuses links and protected system folders, and never overwrites a file already at the destination.

Recovery readiness

Sentinel cannot recover encrypted files; a backup can. On the Recovery page, add the folder your backup tool writes to and press Re-assess. The result (RECOVERY READY, PARTIAL, NO VERIFIED RECOVERY SOURCE or UNKNOWN) is an observation that a recent, independent copy appears to exist. Only a test restore proves a backup works.

Diagnostics

Diagnostics (shown on the home page) answers whether Sentinel itself is working: monitoring state, events received, processed and shed, peak backlog, database state, writes lost, and the integrity of the audit chain and configuration.

  • Verify Now re-checks the audit chain. A failure means stored security records changed outside Sentinel.
  • Acknowledge Lost History… appears only when history is missing and every remaining record verifies (for example after you deleted the data folder yourself). The acknowledgement is itself recorded.
  • Review and Accept Current Settings… appears when the settings file changed outside Sentinel; it shows every security-relevant value before you accept it.
  • Export Diagnostics… contains no keys or file contents, but it does contain file paths. Read it before sharing it.

Settings

Settings holds the detection window, the rule thresholds, the risk thresholds and the alert cooldown, each limited to a safe range. Nothing changes until you press Apply. Folders are managed on Protected Locations, backup folders on Recovery. Security-relevant settings are covered by the integrity check: a change made outside Sentinel is reported, never silently accepted.

C — Technical reference

Architecture

Sentinel is a single user-mode desktop process written in Python with Qt for Python (PySide6). It installs no service and no driver, and runs with the permissions of the signed-in user.

File monitoring
One recursive ReadDirectoryChangesW watch per protected root (through the watchdog library). A supervisor checks every second that each watch is alive, reports an interruption and re-arms it when the folder exists again. A Windows notification-buffer overflow is reported as lost notifications.
Intake
Events reach analysis through a bounded buffer, delivered in time-boxed batches so the interface stays responsive. Under sustained overload only repeat modifications of a file already seen are shed; renames, creations and deletions never are. Every loss is counted and degrades the posture.
Detection
A 30-second sliding window with incremental counters: the cost per event does not grow with the size of a burst. Five rules contribute fixed points to a score bounded at 100.
Process context
A snapshot of running processes every few seconds, used only to suggest a candidate program for an incident. File events themselves carry no process identity.
Persistence
A local SQLite database in write-ahead-log mode for events, detections, alerts, incidents and actions; security records are also committed to the audit chain.
Response
Incident manager, quarantine store, trust records and recovery assessment. Every action is user-initiated.

Data storage

Everything Sentinel records stays in %LOCALAPPDATA%\RansomwareSentinel in your user profile, never in the program folder:

  • the database: events, detections, alerts, incidents, the actions you took, trust records and the audit chain itself;
  • the audit chain's anchor and its key, protected with Windows DPAPI for your account;
  • rotating application logs, the settings file, the quarantine store and the demo workspace.

Raw telemetry (events and detections) is capped at 500,000 rows each, oldest first; incidents, alerts and the audit chain are never pruned. Uninstalling keeps this folder on purpose, because it can hold the only record of an incident and any quarantined files. Nothing in it is sent anywhere.

Integrity model

Security records (incidents, trust decisions, quarantine actions, retention and configuration) are committed to an append-only chain: each entry carries an HMAC-SHA256 over its content and the previous entry. Two references record the chain's head: an anchor in the data folder and a witness in the current user's registry, outside the data folder.

  • Verification runs at start-up and on demand. A modified, removed or reordered record, an older database put back with its older anchor, and a deleted witness are all reported as tampering.
  • Settings are covered by the same chain: a change made outside Sentinel is reported until you review and accept it.
  • The chain detects tampering after the fact; it cannot prevent it. A program running as you that restores an old copy of the data folder and of the registry witness can roll the record back undetected.

Unusual file names

Names Windows allows but that cannot be represented exactly (for example unpaired UTF-16 surrogates) are recorded with a replacement character, and Sentinel will not act on a file whose recorded name may refer to a different file.

What is and is not observed, and every limitation, are listed in How it works.

D — Help

Updating and uninstalling

Sentinel never connects to the internet, so it does not check for updates. To update, run a newer installer from the download page; it replaces the program and keeps your settings and records.

To uninstall, close Sentinel, open Settings → Apps → Installed apps (Windows 10: Apps & features) and uninstall Ransomware Sentinel. Your records in %LOCALAPPDATA%\RansomwareSentinel are kept; delete that folder yourself if you no longer need them. If you reinstall after deleting it, Sentinel reports the missing history once, and you confirm it with Acknowledge Lost History… in Diagnostics.
