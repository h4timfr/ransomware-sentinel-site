Getting started

Ransomware Sentinel watches the folders where your own files live and recognises the behaviour typical of ransomware: bursts of file changes, mass renaming, and renames to encrypted-looking extensions such as .locked. It gives that activity a risk score from 0 to 100, explains every point of the score, groups related alerts into one incident, and helps you investigate and respond.

  1. Download and install Sentinel.
  2. It opens with a short setup. Keep the suggested folders ticked, press Start Protection, and wait for PROTECTION ACTIVE.
  3. Leave Sentinel open while you use your computer. The Next step box on the dashboard always tells you the one thing worth doing next.
  4. If Sentinel raises an alert, open the incident it points to and read Why this is suspicious. The alerts and incidents section explains what to do.

Keep your other protection. Sentinel is not antivirus and does not replace Microsoft Defender. Keep Defender (or your antivirus) on and keep backups of the files that matter.

Installing

Download {{installerFile}} from the download page and open it. Setup asks whether to install for all users (recommended; Windows asks for permission) or only for you (no administrator rights needed), shows a short "Before you install" summary, and offers a desktop shortcut. When it finishes it can open Sentinel straight away.

Requirements: {{windows}}. Python, Git and the command line are not needed.

The installer is not code-signed yet, so Windows may show a SmartScreen warning. The download page explains what it means and how to check the file.

Sentinel keeps its records in %LOCALAPPDATA%\RansomwareSentinel (your user profile), never in the program folder.

First-run setup

The first time Sentinel opens, a four-step setup appears over the main window.

Step 1: Welcome

Four lines on what Sentinel does and, just as plainly, what it does not do. Press Start Setup. (Not Now closes setup; reopen it later from Help → Run Setup Again.)

Step 2: Protected locations

Sentinel lists the folders where your own files normally live, ticked: Desktop, Documents, Downloads, Pictures, Videos and Music. It finds them through Windows itself, so a Documents folder moved to OneDrive or another drive is found where it really is. If OneDrive is set up it is listed unticked, because its sync client creates and renames files in bursts that can raise alerts. Untick anything you don't want watched and press Continue.

Step 3: Initial scan

Leave Start protection automatically when Sentinel opens ticked if you want protection to start by itself each time you open Sentinel. Press Start Protection. The initial scan runs; Skip Scan stops it early (monitoring keeps running). When the panel says PROTECTION ACTIVE, press Continue.

Step 4: Protection active

The last screen shows what is running and offers Take Guided Tour, Explore Dashboard or Run Safe Demo. The first time, the guided tour starts by itself unless you choose the demo.

The guided tour

The tour dims the window, outlines one real control at a time and explains what it is for. Use Next, Back and Skip Tour, the arrow keys, or Esc. Replay it any time from Help → Guided Tour or the Getting Started page (in the sidebar's Learn group). Help → Quick Reference (F1) opens a one-page summary.

Protected locations

The Protected Locations page lists every protected folder and whether it can actually be watched.

StateMeaning
WatchedActivity in this folder is observed while protection runs.
CoveredThe folder is inside another protected folder, which is watched instead (it is not watched twice).
MissingThe folder does not exist right now (for example a disconnected drive). It stays listed and is watched again when it returns.
No accessSentinel does not have permission to read it.
Junction – not followedThe folder is a link that could point elsewhere; it is not followed.
OffYou unticked it. It stays in the list.
  • Tick or untick a folder to protect it or stop watching it.
  • Add Location… adds any other folder. Adding a whole drive or a Windows or Program Files folder shows a warning first, because it produces far more activity and permission errors.
  • Remove… takes a folder off the list. Re-check asks every folder for a fresh answer.

Starting and stopping protection

Start and stop protection with the toolbar (Ctrl+Shift+M and Ctrl+Shift+S) or the protection panel on the dashboard. Protection moves through clear states:

StateMeaning
PROTECTION OFFNothing is being watched. Press Start Protection.
STARTING PROTECTIONProtected locations are being checked (at most about 15 seconds for slow network folders).
INITIAL SCANMonitoring is running; existing files are being listed.
PROTECTION ACTIVEContinuous monitoring of your protected locations is running.
STOPPINGProtection is being stopped.
PROTECTION NOT STARTEDSomething failed; the message says what (for example, no folder can be watched).

Protection runs only while Sentinel is open. Closing the window stops it. Sentinel does not start with Windows by itself: open it when you start your computer, and tick Start protection automatically when Sentinel opens so it begins watching straight away.

"Protection active" means monitoring of your protected locations is running. It is not kernel-level monitoring and not a guarantee.

The initial scan

Whenever protection starts, Sentinel first lists the files already in your protected locations and checks their names for encrypted-looking extensions. It does not open, read or change any file. Continuous monitoring starts before the scan, so your folders are watched while it runs. Listing file names produces no file activity, so the scan itself is never mistaken for ransomware.

ShownMeaning
Files examinedHow many files were listed.
Suspicious namesFiles whose extension is on the suspicious list (for example .locked). A name is not proof of encryption.
Skipped / inaccessibleFolders that could not be read and were passed over.
Initial scanNOT RUN, RUNNING, COMPLETE, CANCELLED or FAILED.

The dashboard

  • Next step: one recommended action, decided from the current state: set up protection, start it, open an incident, fix a location, add a backup location, or try the demo.
  • Protection panel: the protection state, your locations (watched, covered, missing…), the initial scan results, and whether the filesystem and process monitors are active.
  • Security Posture: Sentinel's verdict on its own monitoring: PROTECTED, MONITORING, DEGRADED, ERROR, CRITICAL THREAT or MONITORING OFF. PROTECTED means the monitoring is working on your protected locations, not that the computer is safe. Only a critical incident changes it to CRITICAL THREAT; while a lower-severity incident is open it stays PROTECTED and says the incident is still open.
  • Active Threat State: the current risk score and the number of active and critical incidents.

Alerts and incidents

An alert is one suspicious detection: its severity, risk score, the rules that fired, how many files were affected, and the incident it belongs to. Alerts are raised from a HIGH score (60 or more).

Rule (30-second window)Default triggerPoints
Rapid file modification50 modifications25
Mass file rename20 renames25
Suspicious extension1 or more renames to, for example, .locked20
Mass file creation50 new files15
High event concentration75 events15

Scores map to LOW (1–29), MEDIUM (30–59), HIGH (60–79) and CRITICAL (80–100).

An incident groups the alerts from one episode into one case. On the Incidents page, active cases are listed first. Select one and press Investigate Selected (or double-click it).

StatusMeaning
OPENNew; nobody has acted on it yet.
INVESTIGATINGYou marked it as being looked into.
CONTAINED / QUARANTINEDA file attributed to it was contained.
RESOLVEDClosed after investigation.
DISMISSEDClosed as not a threat (for example a demo incident, or something you did yourself).

What to do when Sentinel raises an alert

  1. Don't panic, and don't delete anything yet. Open the incident from the Next step box or the Incidents page.
  2. Read Why this is suspicious and File activity. Were you doing something that changes many files at once, such as renaming photos, extracting an archive or syncing a folder? Then it may be you.
  3. If it wasn't you: disconnect from the network, run a full scan with Microsoft Defender (or your antivirus), and check your backups. Sentinel does not stop programs itself.
  4. Record what you decided: Mark Investigating, then Mark Resolved… or Dismiss….

Investigating an incident

  • Forensic record: whether the incident's stored record still matches what was committed to the audit chain.
  • Response: where containment stands and every available action.
  • What was observed: risk, process and attribution, files affected, first and last seen. Attribution is usually UNKNOWN: file events do not say which program made a change, and Sentinel does not guess.
  • Why this is suspicious: the rules and points behind the score.
  • File activity: what happened to each file, following renames as one file.
  • Timeline: every recorded action, who did it and the real outcome.

Actions: Acknowledge, Mark Investigating, Mark Resolved…, Dismiss…, Quarantine…, Trust Artifact… and Export Report…. Every action is confirmed and recorded in the incident's audit trail.

Quarantine

Quarantine is available only when an incident names a program file (an executable). Because attribution is usually UNKNOWN, often there is nothing to quarantine, and Sentinel says so.

Quarantining moves that file into Sentinel's quarantine store and renames it, so it no longer has an executable extension and its original path no longer resolves. This is containment, not isolation: a program running as you can still read the stored bytes, anything with higher privileges is not contained, and Sentinel does not stop the program.

To restore, select the item on the Quarantine page and press Restore Selected…. Sentinel checks that the file is byte-for-byte the one it quarantined and never overwrites an existing file.

Recovery readiness

Sentinel cannot recover encrypted files; a backup can. The Recovery page checks whether a recent, independent copy of your data appears to exist in the backup locations you add.

  1. Press Add Backup Location… and choose the folder your backup tool writes to.
  2. Press Re-assess. The result is RECOVERY READY, RECOVERY PARTIAL, NO VERIFIED RECOVERY SOURCE or RECOVERY UNKNOWN.

This is an observation, not a recovery. Only a test restore proves that a backup works.

Diagnostics and audit

Diagnostics shows whether Sentinel itself is working: monitoring state, posture, events received, processed and shed, database state, retention, and the integrity of the audit chain and configuration. The audit information lives here; there is no separate audit page.

  • Verify Now re-checks the HMAC-chained audit log. A failure means stored security records may have been changed outside Sentinel.
  • Export Diagnostics… or Copy to Clipboard for support. The export contains no keys or file contents, but it does contain file paths: look at it before sharing it.
  • Logs lists every security action and event; File → Export Logs saves the log files.

Safe Demo

The Demo Center is the safe way to see, or to show someone, the whole workflow. It creates, edits and renames inert text files in its own isolated workspace inside Sentinel's data folder, and nowhere else. It encrypts nothing, touches none of your files, ends no process and changes no system setting. It is not real ransomware; everything after the synthetic files is the real product.

  1. Open Demo Center (Learn group in the sidebar).
  2. If an earlier run left anything behind, press Reset Demo… first.
  3. Press Start Demo. If protection is off, the demo starts monitoring and stops it again on reset.
  4. Follow the progress list; each step turns green only when the product has actually done it.
  5. Use the Presenting it buttons to show Activity, the Dashboard, Alerts and the incident.
  6. Open the incident and press Acknowledge, then return and press Verify Audit Chain and Assess Recovery.
  7. Press Reset Demo… and confirm. The synthetic files are removed and the demo incident is dismissed; records are kept.

Start Demo is refused while another incident is active, so a demo alert can never be merged into a real case. The demo incident has no program to attribute, so quarantine and trust are not available for it; that is the product's real attribution limit, not a demo shortcut.

Settings

Settings holds the detection window, the behaviour thresholds, the risk thresholds and the alert cooldown. The defaults suit most people. Nothing changes until you press Apply; applied settings are saved and take effect immediately. Protected folders are managed on the Protected Locations page, and backup folders on the Recovery page.

Uninstalling

Close Sentinel, then open Settings → Apps → Installed apps (Windows 10: Apps & features), choose Ransomware Sentinel and Uninstall. The program is removed; your records in %LOCALAPPDATA%\RansomwareSentinel are kept on purpose (they can hold the only copy of an incident's history and of quarantined files). Delete that folder yourself if you no longer need it. If you install Sentinel again after deleting it, Sentinel reports the missing history once (its tamper check cannot tell a deleted folder from a wiped one); press Acknowledge Lost History… in Diagnostics to confirm it.

Limitations

  • Not antivirus, and not a replacement for Microsoft Defender or an enterprise endpoint (EDR) product.
  • User-mode only: no kernel driver, ETW consumer or minifilter.
  • Only protected locations are watched, and only while Sentinel is open; activity anywhere else is not observed.
  • OneDrive's sync activity can look like ransomware, which is why OneDrive is off by default.
  • Process attribution is usually UNKNOWN; a named program is a candidate, not proven cause.
  • No process termination or write blocking: Sentinel detects and records; you act.
  • No decryption and no recovery of encrypted files; recovery readiness only checks for a backup.
  • Quarantine is containment, not isolation.
  • The audit chain detects tampering afterwards; it cannot prevent it.
  • Only a CRITICAL incident changes the posture from PROTECTED; a HIGH incident is shown as an open incident instead.
  • On small screens, the sidebar's Learn group can sit below the fold; scroll the sidebar (the guided tour does this for you).
  • It cannot guarantee that every ransomware family is detected.
