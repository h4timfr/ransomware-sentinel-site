How it works · version {{version}}

From a file event to an incident

Eight steps, from the folders you choose to the record of what happened. Every number on this page is the shipped default in version {{version}}.

  1. Step 1 · Scope

    You choose the folders

    First-run setup proposes the folders where your own files live, resolved through the Windows Known Folder API, so a Documents folder redirected to OneDrive or another drive is found where it really is. Nothing outside these folders is watched.

    Proposed
    Desktop, Documents, Downloads, Pictures, Videos, Music. Untick any of them, or add your own.
    Off by default
    OneDrive. Its sync client renames files in bursts that look like an attack. Switch it on if you want it watched.
    Never proposed
    Drive roots, the Windows folder and Program Files. Adding one by hand shows a warning first.
    Honest coverage
    Each folder reports Watched, Covered, Missing or No access. Junctions are not followed. A folder deleted and recreated is watched again, and the gap is reported.
  2. Step 2 · Observation

    Sentinel observes filesystem activity

    Each protected folder gets one recursive Windows file-change watch (ReadDirectoryChangesW). A supervisor checks every second that each watch is alive and re-arms it when it can. Monitoring runs in user mode, only while Sentinel is open.

    Observed

    • File and folder creation, modification, deletion and renames, with their paths and times
    • During the initial scan, the names of files already there
    • A list of running processes every few seconds, for context only

    Not observed

    • File contents: no file is opened or read
    • Anything outside the protected folders
    • Network traffic, the registry, or which process made a change

    Under a flood of activity, only repeat modifications of a file already seen are shed; renames, creations and deletions never are. Every loss is counted and shown, and the posture becomes DEGRADED.

  3. Step 3 · Signals

    Five behavioural signals are evaluated

    Every event is counted into a sliding 30-second window. A signal fires while its count in the window is at or over its threshold.

    SignalFires when, within 30 secondsPoints
    Rapid file modification50 file modifications+25
    Mass file rename20 renames+25
    Suspicious extensionOne file changed to a listed extension (.locked, .encrypted, .crypted, .enc, .ransom, .lock), or 10 changed to unfamiliar extensions. A change is a rename, or a copy with a new extension followed by deletion of the original.+20
    Mass file creation50 new files+15
    High event concentration75 file events of any kind+15

    There are no other rules: no malware signatures and no trained models. The thresholds and the window can be changed in Settings within fixed bounds.

  4. Step 4 · Score

    Signals add up to a 0–100 risk score

    The score is the sum of the points of every signal currently over its threshold, recalculated as each event arrives and never more than 100. Because the points are fixed, the score always decomposes into its reasons.

    Single signal
    At most 25, which is LOW. One kind of burst alone never reaches MEDIUM, let alone an alert.
    HIGH (60+)
    At least three signals together, for example 25 + 20 + 15 = 60.
    CRITICAL (80+)
    At least four signals together, for example 25 + 25 + 15 + 15 = 80.

  5. Step 5 · Classification

    The score maps to a risk band

    Every event is recorded with the risk at that moment and the signals that fired. The HIGH and CRITICAL thresholds can be changed in Settings within fixed bounds.

    LOW1–29

    Recorded with the event. Nothing is raised.

    MEDIUM30–59

    The event is marked Review on the Activity page.

    HIGH60–79

    The event is Flagged, an alert is raised, and related alerts are grouped into one incident.

    CRITICAL80–100

    A critical alert. A climb from HIGH is reported at once, never held back.

  6. Step 6 · Alert

    HIGH raises an alert and opens an incident

    An alert carries the score, the signals and the files involved. Alerts from one episode are grouped into one incident, and a 30-second cooldown stops a single burst from raising dozens of alerts. While a HIGH incident is open, the posture stays PROTECTED and says that an incident needs attention. Alerts appear in Sentinel's window; nothing is sent anywhere.

  7. Step 7 · Response

    CRITICAL changes the posture. You choose the response.

    At CRITICAL, the security posture becomes CRITICAL THREAT and stays so while the critical incident is open. That is the only thing CRITICAL changes automatically: at no level does Sentinel block a program, stop a file change, quarantine or delete anything by itself.

    Triage
    Acknowledge, investigate, resolve or dismiss. Each action is confirmed and written to the incident's audit trail.
    Contain
    Quarantine a program file the incident names, if it names one. Containment, not isolation: Sentinel does not stop the program. Quarantine and restore
    Recover
    Sentinel cannot decrypt files. Recovery readiness checks that a recent, independent copy appears to exist in your backup folders.

    When an alert appears: don't delete anything yet. Read Why this is suspicious. If it wasn't you changing many files, disconnect from the network, run a full scan with Microsoft Defender or your antivirus, and check your backups. Then record the outcome in the incident.

  8. Step 8 · Record

    The incident is recorded, tamper-evidently

    An incident shows the rules and points behind the score, what happened to each file (following renames as one file), the first and last activity, a candidate program if one could be inferred, and a timeline of every action taken.

    Attribution
    Windows file events do not say which program made a change. Sentinel reports UNKNOWN rather than guessing; a program it does name is a lead, not proof.
    Audit chain
    Incidents, trust decisions, quarantine actions and configuration are committed to an append-only HMAC-SHA256 chain, verified at start-up and on demand. Edited, removed or rolled-back records are reported. Integrity model
    Where
    On your PC, in %LOCALAPPDATA%\RansomwareSentinel. Exports are files you choose to save; they contain paths, never file contents or keys.

Limitations

What Sentinel cannot do

Behavioural detection is one layer. These limits are why it belongs alongside Microsoft Defender and tested backups.

  • Not antivirus, and not a replacement for Microsoft Defender or an endpoint detection and response (EDR) product.
  • User mode only: no kernel driver, ETW consumer or file-system minifilter. Only protected folders are watched, and only while Sentinel is open.
  • Heuristic and rate-based. Files encrypted in place without renaming, or slowly enough that no 30-second window looks unusual, stay below an alert (in-place encryption reaches at most MEDIUM). Novel behaviour may match no signal.
  • Attribution is usually UNKNOWN; a named program is a candidate, not proven cause.
  • No blocking, process termination or write prevention. Sentinel detects and records; you act.
  • No decryption or recovery of encrypted files. Recovery readiness only checks that a backup appears to exist.
  • Quarantine is containment, not isolation.
  • Ordinary bursts can raise alerts: OneDrive sync, extracting archives, bulk photo imports.
  • Under a flood beyond what it can analyse, Sentinel sheds routine events and reports it; the window can pause for a few seconds at the peak.
  • After a crash or if it is ended, nothing is watched until Sentinel is opened again. It does not start with Windows on its own.
  • Windows only. There is no macOS or Linux version in the current release.
