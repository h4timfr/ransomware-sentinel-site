## Ransomware Sentinel 1.3.1

**A security hardening update.** It fixes the findings of the security
review of 1.3.0. Detection rules, scoring weights, the alert threshold and the
database are unchanged; your settings, history and incidents carry over.

- Works on Windows 10 (version 1809 or later) and Windows 11, 64-bit. Tested on Windows 11.
- Free. Runs entirely on your computer; it has no internet features.
- **Not code-signed yet**, so Windows SmartScreen may warn about an unknown
  publisher. Download it only from the [official download page](https://h4timfr.github.io/ransomware-sentinel-site/download/),
  and compare its SHA-256 checksum (below and in `RansomwareSentinel-Setup.exe.sha256`).
  Never turn off Defender or SmartScreen to install it.

### What changed

**A harder-to-fool audit record**
- Sentinel now keeps a small marker of its latest audit record outside its
  data folder. Putting back an older copy of the database, or deleting it,
  is now reported as tampering instead of looking like a clean or new
  installation.
- If history was genuinely lost (and nothing that remains was altered),
  Diagnostics lets you acknowledge it; the acknowledgement is recorded. This
  also applies if you deleted Sentinel's data folder yourself and then
  reinstalled: Sentinel reports the missing history once, and you confirm it
  with **Acknowledge Lost History** in Diagnostics.

**Settings you can trust**
- "Start protection automatically" and the log folder are now covered by the
  settings integrity check.
- A settings file that changed outside Sentinel is no longer accepted by the
  next save. Diagnostics shows every security-relevant value before you
  accept them.
- Out-of-range values in the settings file are rejected.

**Monitoring without gaps**
- Monitoring now starts before the initial scan, so your folders are watched
  while it runs.
- If Windows drops change notifications under heavy load, Sentinel now says
  so instead of staying silent.
- The log folder setting can no longer hide a protected folder from
  monitoring.

**Detection**
- Files renamed to unfamiliar extensions (not only `.locked`, `.encrypted`
  and the like), and copies with a new extension whose originals are then
  deleted, now count towards the suspicious-extension rule. Everyday
  conversions (photos, archives, downloads, log rotation) do not.
- Large bursts of renames no longer slow Sentinel down.

**Quarantine, restore and start-up**
- Restoring a quarantined file never overwrites an existing file and refuses
  links, junctions and hard links.
- A leftover lock file can no longer stop Sentinel from starting.

### Please keep in mind

Ransomware Sentinel watches the folders you choose while it is open. It is
not antivirus and does not replace Microsoft Defender, it does not stop
programs or block file changes, and it cannot decrypt or recover files. It
cannot guarantee that every attack is detected: for example, files encrypted
in place without being renamed still reach at most a MEDIUM score. Use it
alongside your antivirus and regular backups. The [documentation](https://h4timfr.github.io/ransomware-sentinel-site/docs/#limitations)
lists every limitation.
